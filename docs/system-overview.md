# 系統運作說明（給非工程背景同事看的）

這份文件不講怎麼操作、怎麼設定，只講「這套系統整體是怎麼運作的」——目的是讓你看得懂它在做什麼、為什麼有時候不回覆、告警訊息是什麼意思，遇到狀況時知道問題大概出在哪一環。操作類的內容（怎麼申請邀請碼、怎麼幫學員綁定）另外有介面上的說明，這裡不重複。

## 一句話說明

每一位學員都有一個**專屬的 LINE 官方帳號**，綁定一份**只屬於他自己的車輛資料庫**（用 Google 的 NotebookLM 建立）。客戶在 LINE 上問車，系統會去讀這份資料庫、整理出答案，用學員自己官方帳號的身分回覆客戶。

## 整體運作方式

把這套系統想成一位**24 小時待命、只讀過這位學員上傳資料的助理**，坐在學員的 LINE 官方帳號後面：

1. 客戶在 LINE 上跟學員的官方帳號提問（1:1 私訊，或在有拉這個官方帳號的群組/多人聊天室裡 @ 提問）。
2. 系統收到這則訊息，先判斷「這是不是在問車」。
3. 如果是，系統去查這位學員專屬的車輛資料庫（裡面是學員自己上傳的型錄、現車清單等文件），把找到的內容整理成一段話。
4. 系統把整理好的答案，用這位學員的官方帳號身分回覆給客戶。

每個學員的資料庫彼此獨立——A 學員的客戶問問題，永遠只會查到 A 學員自己上傳的資料，不會混到別人的。

## 系統怎麼判斷「該不該回覆」

這套系統不是「什麼訊息都照單全收、照單全回」，它會做幾層判斷，這是刻意設計、不是故障：

- **不是在問車的閒聊，會被禮貌拒答**。系統只讀過學員上傳的車輛資料，硬要回答資料庫以外的問題只會亂猜，所以問到不相關的事（天氣、時事、跟車完全無關的閒聊）會收到一句制式的婉拒訊息，而不是被亂回答。
- **正在聊車聊到一半的追問，會被放行**。如果客戶剛問完車、接著在 10 分鐘內追問一句「其他的呢？」「還有嗎？」這種沒有再提到車型名稱的句子，系統知道這是同一輪對話的延續，不會因為這句話本身沒有車輛關鍵字就打回票。超過 10 分鐘沒有互動，就會被當成新的一輪重新判斷。
- **群組裡的「賀成交」報喜貼文，完全不會被回覆**。經銷商群組常見的「賀成交！恭喜客戶入主 XX」這種同仁公告，因為文字裡常常會提到真實車型名稱，以前容易被系統誤判成在問車而跳出來回覆——現在這類報喜用語（含「賀」「成交」）會被系統整句忽略，不管在群組或 1:1 都一樣，安靜不回覆。
- **涉及交易、買賣、議價、簽約等敏感字眼，不會給出實質承諾**。系統的角色定位是「諮詢用」，遇到這類問題只會回覆一句制式說明（不可回答交易相關事宜），並不會，也不能代替學員本人去談價格或簽約。

## 回答的呈現方式

- 如果答案牽涉到**好幾家廠商**的資料，系統會自動把回答拆成好幾則、分開發送，每一則開頭會標明是哪一家廠商的資訊，避免不同廠商的內容混在同一段裡看不清楚。
- 如果客戶要求**比較多個車型**，系統會盡量用表格呈現，方便一次看完差異。
- 如果符合條件的廠商很多（4 家以上），系統為了不讓客戶在 LINE 上等太久，會先給一個精簡總覽（廠商名稱 + 台數），而不是一次把每家的完整規格都生成出來，客戶可以再追問想深入了解的廠商。

## 幕後的自動保護機制（你不需要操作，但知道它存在會安心一點）

系統背後有幾個自動運作、不需要人手動盯著的機制：

- **登入保鮮**：系統跟 Google NotebookLM 之間的登入憑證會定期自動檢查、自動續期，避免因為長時間沒操作被系統登出。
- **健康檢查**：系統會定期自我檢查是否還正常運作（服務有沒有掛掉、對外連線是否還通）。
- **異常告警**：一旦偵測到異常（例如某位學員的登入失效、查詢一直失敗、服務掛掉），系統會**主動**通知負責維運的工程同事，不需要等學員或客戶反映才發現問題。告警目前可能會經由 LINE、Google Chat 或 Telegram 其中一種或多種管道送出，看維運同事怎麼設定；同一個問題在還沒解決前不會重複灌訊息，只有真正需要處理時才會通知。

也就是說，如果哪位學員的機器人突然不回覆或回覆怪怪的，**維運同事通常已經同時收到告警了**，不一定需要你額外通報，但主動反映一下仍然有幫助（尤其是「感覺答案內容不對」這種系統不會自動偵測到的狀況，跟服務有沒有掛掉是兩回事）。

## 常見疑問

**Q：客戶問的問題明明跟車有關，為什麼機器人沒回？**
可能原因：問題被誤判成閒聊（例如敘述方式很間接、沒有提到任何車輛相關字詞，又不是緊接在剛才的車輛話題之後）；或剛好觸發了報喜貼文的忽略規則（訊息裡出現「賀」或「成交」）；也可能是學員的登入憑證剛好失效中（這種情況維運同事應該已經收到告警在處理）。

**Q：機器人回答的資料是從哪來的？會不會亂編？**
一律來自學員自己上傳到 NotebookLM 的文件（型錄、現車清單等），系統本身不會憑空編造車輛規格或現況——如果學員沒上傳某項資訊，系統查不到，通常會照實說沒有相關資料，而不是亂猜一個答案。

**Q：同一個問題，換一家廠商問結果會不會不一樣？**
每位學員的資料庫是各自獨立的，機器人只會依照「這位學員自己上傳了什麼資料」回答，不會去比對或引用其他學員的資料。

**Q：發現機器人回答內容有錯，或格式很怪，該找誰？**
內容錯誤（例如規格寫錯、車型搞混）通常代表學員上傳的來源資料需要更新或修正，先確認上傳的文件本身；如果是機器人完全沒反應、或連續多筆回覆都失敗，這比較像是系統面的問題，找負責維運的工程同事處理即可，不需要自己排查。
